# Night Code 1395

중학교 3학년 「별과 우주」 단원 **수업 두 차시(각 45분)를 처음부터 끝까지 진행하는 학습 도구**.
단순 측정 도구가 아니라, 교사가 화면을 순서대로 넘기면 그것이 곧 수업이 되도록 만들었다.

국보 **천상열차분야지도**를 소재로, 학생이 별 자국의 크기를 직접 재어
"밝은 별일수록 크게 새겼다"는 규칙을 스스로 발견한다.

## 8단계 진행

| 단계 | 화면 | 하는 일 |
|---|---|---|
| 1 | 인트로 | "1395년, 조선…" 문구가 천천히 떠오른 뒤, 다음 장면에서 **수업 코드로 함께 붙는다** (2화면) |
| 2 | 지도 소개 | 이름 풀이 / 대동강에 빠진 별지도 / 별이 알려 준 고구려 하늘 / 숫자로 보기 / 돌이 겪은 일 / 만원권 뒷면 — 이야기 카드 6장 |
| 3 | 확대해 들어가기 | 전체 지도에서 삼수 영역으로 줌인 애니메이션 |
| 4 | **두 지도 비교** | 채색본 ↔ 각석본, 같은 별 3개 확대 대조, 세 층(밤하늘→종이→돌) 밀어보기, **학급 실시간 예상 투표**, **영상** (4화면) |
| 5 | 겉보기 등급 | 밝기 차이 → **히파르코스와 등급의 유래** → **"숫자가 작을수록 밝다"** → 0·마이너스 등급 → **포그슨의 100배 규칙** → **밝기 순서 맞히기(카드 게임)** → **우리 곁의 천체 등급표** (7화면) |
| 6 | 측정하기 | 핀 10개, 확대 측정 뷰, 두 손잡이로 지름 재기, 2차 측정·평균, **교사 화면에는 별마다 몇 명이 쟀는지** |
| 7 | 결과 확인 | 표 → 점 그래프(애니메이션) → "이런 걸 산점도라고 한다" → 경향선, **[내 결과 ↔ 우리 반 전체] 전환** |
| 8 | 결론 | 내 결론 쓰기 → 정리 문구 → **친구들의 결론이 양옆에 흐른다** → 두 지도의 의미 → 예상 되돌아보기 → 다음 시간 예고 |

교사는 단계 표시줄로 어느 단계로든 즉시 건너뛸 수 있고,
설명 중심 화면(2·3·4·7)에는 작은 [건너뛰기 ▸] 버튼이 있다.

## 특징

- **Cloudflare Worker 하나로 끝난다** — 외부 데이터베이스·로그인·CDN 없음.
- 학생 기기가 처음 받는 코드는 **약 148KB**. 교사만 쓰는 캘리브레이션과 데모봇은
  필요할 때만 따로 읽어, 학생 태블릿에서는 내려받지도 해석하지도 않는다.
- **실명·학번·반은 서버로 가지 않는다.** 진행 상태와 원본 측정값은 localStorage에 남고,
  학급 기능에서는 학생이 스스로 정한 **닉네임**과 함께 보려고 올리는 것만 오간다.
- 바닐라 HTML/CSS/JS. 그래프·도식·삽화·밤하늘까지 전부 **코드로 직접 그린다.**
- 터치 우선 — 모든 버튼과 손잡이가 **44px 이상**, 화면 확대 방해 없음, 글자 크기 3단계.
- 휴대폰·태블릿·컴퓨터를 모두 확인했다. 좁은 화면에서는 기록표가 **카드로 접히고**,
  눕힌 화면에서는 측정 창이 **두 단**이 되어 [기록하기] 가 늘 보인다.
- 새로고침해도 이어서 진행된다. 도움말 안의 [전체 초기화]로 리셋.
- 정보를 색에만 기대지 않는다(완료 핀은 ✓, 집계는 숫자 병기).

## 단계 4의 세 층 — 밤하늘 → 종이 → 돌

손잡이를 오른쪽으로 밀면 새 층이 **왼쪽에서부터** 덮어 온다.
하늘에 있던 별이 종이에 옮겨지고, 다시 돌에 새겨지기까지의 순서다.

1. **실제 밤하늘** — 맨 아래. 사진이 아니라, 각석본에서 찾아낸 자국 542개를
   지름에서 등급으로 되돌려(지름 = 31.3 − 4.01 × 등급) 밝기로 그린 것
2. **종이(채색본)** — 별의 위치는 정확하지만 크기가 모두 같다
3. **돌(각석본)** — 맨 위. 별마다 크기가 다르다

맨 아래 층 덕분에 "돌에 새긴 크기를 밝기로 읽으면 이런 하늘"이 눈으로 보인다.
자료는 `assets/js/skydata.js` 에 미리 구워 두어 태블릿에서 이미지 분석을 하지 않는다.

밝은 별은 가운데가 빈 고리라 침식하면 덩어리가 조각나 중심이 어긋난다. 그래서 광선
바깥 끝점들의 무게중심으로 중심을 세 번 다시 잡고, 지름은 36방향 광선 길이의 **75번째
백분위수 × 2** 로 삼는다(학생에게 안내하는 "바깥 테두리의 바깥쪽 끝" 기준과 같다).
이렇게 재면 확정된 별 10개에서 등급과의 상관이 **−0.734** 로, 교사가 손으로 잰 값과 같다.
별자리 선이 붙어 있으면 자동 검출이 놓치므로, 좌표를 확정한 별 10개는 그 좌표와 등급으로
덮어쓴다 — 삼수의 별이 빠지지 않도록.

## 학급으로 같이 하기 (단계 1에서 참여)

수업 첫 화면에서 다 같이 붙는다. **교사가 화면을 넘기면 학생 화면도 같이 넘어간다.**

1. 인트로 문구가 끝나고 [시작하기] 를 누르면 참여 화면이 나온다.
   교사가 **[수업 열기]** → 6자리 수업 코드가 뜬다. 이 코드를 불러 준다
2. 학생은 자기 기기에서 **[코드로 참여하기]** → 코드와 **닉네임**을 넣는다
3. 교사 화면에 참여자 명단이 뜬다. 접속이 끊긴 학생은 흐리게 보인다
4. 이후 교사가 단계를 넘길 때마다 학생 화면이 따라온다
5. 단계 4에서 예상을 고르면 모든 화면의 막대가 실시간으로 움직인다
6. 단계 5-6에서 학생이 낸 밝기 순서가 교사 화면에 표로 모인다
   (단계 6에서는 별마다 몇 명이 쟀는지가 표에 함께 나온다 — 1차만 재도 센다)
7. 단계 7에서 [우리 반 전체]를 누르면 반 전체의 산점도와 평균 경향선이 나온다
8. 단계 8에서 결론을 쓰면 친구들의 결론이 포스트잇처럼 양옆에 흐른다

- **학생은 따라가기를 끌 수 있다.** 상단 띠의 [따라가는 중]을 누르면 멈추고,
  다시 누르면 곧바로 교사 화면으로 돌아간다. 단계 6처럼 각자 속도로 재야 할 때 쓴다
- **별을 재는 중에는 화면을 빼앗지 않는다.** 측정 창을 닫을 때 밀린 단계로 따라간다
- **한 기기 한 표.** 다시 고르면 바뀌고 쌓이지 않는다
- 교사 화면의 명단에는 **누가 아직 안 골랐는지**만 보인다. 무엇을 골랐는지는 보이지 않는다
- 서버로 가는 것은 기기마다 만든 **무작위 토큰**과, 수업 중에 함께 보려고 올리는 것뿐이다 —
  학생이 정한 **닉네임**, 고른 **예상**, **밝기 순서 답**, 잰 **자국의 크기**(등급·지름 짝), **결론 한 문장**.
  실명·학번·반은 보내지 않는다. 닉네임 12자·결론 300자로 자르고 태그 기호를 지운다
- 12시간이 지나면 그 수업의 기록은 자동으로 지워진다
- **연결이 안 돼도 앱은 그대로 동작한다.** 참여 칸만 조용히 접힌다

구현은 Cloudflare **Durable Object** 하나다(수업 하나 = 객체 하나).
그 안에 상태와 WebSocket 이 함께 있어 외부 데이터베이스가 필요 없고,
SQLite 저장소를 쓰므로 무료 요금제에서도 된다.

## 밝기 순서 맞히기 (단계 5-6)

표를 그냥 읽기 전에 먼저 맞혀 보게 한다. 태양·보름달·금성·목성·시리우스·베가·데네브
일곱 개를 밝은 것부터 놓는다. 카드를 누르면 순서대로 놓이고, 놓은 카드를 누르면 빠진다.

[제출하기] 를 누르면 교사 화면에 **7 × 7 표**가 뜬다. 가로가 순위, 세로가 천체이고,
칸이 진할수록 그렇게 답한 학생이 많다. 실제 순위 자리에는 테두리를 둘러, **대각선이
밝게 켜지면 반이 잘 맞힌 것**이다. 어디서 갈렸는지가 한눈에 보인다(금성과 목성이 흔히 갈린다).

[실제 결과 보기] 를 누르면 단계 5-7 로 넘어가며, 교사가 누르면 학생 화면도 함께 넘어간다.
결과 표에는 학생이 낸 순위가 "내 예상 3위" 처럼 함께 표시되고, 맞힌 것에는 ✓ 가 붙는다.

## 반 전체로 보기

혼자 잰 점 10개로는 흩어짐이 커서 경향이 흐릿하다.
그래서 참여한 학생들의 점을 한 그래프에 모을 수 있게 했다.

- **단계 7** — [우리 반 전체]를 누르면 친구들의 점이 옅게 깔리고,
  경향선을 **모든 점**으로 다시 구한다. 사람이 많아질수록 실수는 서로 상쇄되고
  진짜 경향만 남는다는 것을 눈으로 보게 하는 것이 목적이다.
  잰 것이 없는 기기(교사용)는 처음부터 반 전체가 켜진 채로 열린다.
- **단계 8** — 결론을 쓰고 [모두의 결론 보기]를 누르면 내 결론이 올라가고,
  친구들의 결론이 포스트잇처럼 본문 양옆에 흐른다(왼쪽은 위로, 오른쪽은 아래로).
  손을 올리면 멈춘다. 1400px 미만이거나 인쇄할 때는 흐르지 않고 그냥 늘어놓는다.

올라가는 것은 **[등급, 지름] 짝**과 **결론 한 문장**뿐이고, 산점도용 점은
누가 올렸는지 떼고 좌표만 모은다. 연결이 없으면 두 기능 모두 조용히 접히고
원래대로 내 결과만 보인다.

## 데모봇 — 수업 전에 혼자 돌려 보기

수업을 열면 교사 화면에 **[데모봇으로 시뮬레이션 하기]** 가 나온다.
가짜 학생 12명이 진짜 학생과 똑같이 붙어서, 교사가 화면을 넘길 때마다
그 단계에 맞는 일을 한다.

| 교사가 넘긴 단계 | 데모 학생이 하는 일 |
|---|---|
| 1 | 하나씩 들어온다 (약 0.4초 간격) |
| 4 | 1~7초에 걸쳐 예상을 고른다 (밝기 쪽이 많되 갈리도록) |
| 5-6 | 1~9초에 걸쳐 밝기 순서를 낸다 (금성·목성이 갈리도록) |
| 6 | 별을 하나씩 재 나간다 — 속도가 사람마다 다르고, 끝까지 못 가는 학생도 나온다 |
| 8 | 1~9초에 걸쳐 결론을 쓴다 |

건너뛰어 들어가도 앞 단계에서 했어야 할 일을 몰아서 하므로 빈 화면이 되지 않는다.
사람마다 **치우침(±2.2px)과 흔들림(1.2~4.0px)** 이 달라, 반 전체로 모았을 때
경향이 또렷해지는 모습이 실제와 같이 나온다.

**[데모 멈추기]** 를 누르면 데모 학생이 남긴 것(명단·표·측정값·결론)을 서버에서
모두 지우고 빠진다. 그래서 리허설한 그 코드로 바로 수업해도 데모 자료가 섞이지 않는다.
이미 학생이 참여 중이면 시작 전에 한 번 묻는다.

교사 화면이 새로고침되어 정리 신호를 못 보냈더라도, 다음에 데모를 시작할 때
남아 있던 데모 자료를 먼저 걷어낸다(데모봇 토큰이 `demo-` 로 시작해 구분된다).

## 두 지도의 좌표 관계

`chart_orion.jpg`(각석본)와 `chart_color.jpg`(채색본)는 **같은 하늘을 담았지만 크롭이 다르다.**
채색본이 약 9% 작고 322px 위에 있다. 그래서 좌표를 그대로 쓸 수 없고,
설정의 `colorTransform` 으로 옮긴다.

```
각석본 → 채색본 :  배율 0.9073,  회전 −0.26°,  이동 (75, −322)
```

교사가 두 지도에 같은 별 6개를 표시해 준 대응으로 구했고 잔차는 2~16px다.
단계 4의 별 3개 확대와 밀어보기가 이 값을 쓴다.
채색본이 각석본 위쪽 355px 을 덮지 못하므로, 밀어보기는 겹치는 영역만 보여 준다.

## 무엇을 재는가 (측정 기준)

원본 유물을 확대해 보면 **밝은 별일수록 크고 깊게 파여 가운데가 비고 테두리만 진한 "고리"**로 보인다.
어두운 별은 작고 속이 찬 점에 가깝다. 따라서 측정 대상은 '가장 긴 지름'이 아니라
**바깥 테두리의 바깥쪽 끝에서 끝까지의 지름**이다.
앱은 이 기준을 코드로 그린 고리 도식과 함께 측정 화면·도움말·인쇄물에서 안내한다.

측정 뷰의 확대 배율은 자국이 화면에서 **최소 60px 이상**으로 보이도록 자동으로 잡는다
(자국 8~60px → 3~14배).

## 교사 준비 순서

주소 뒤에 **`?admin=1`** 을 붙이면 캘리브레이션 모드로 들어간다.

1. **① 측정 핀** — [별 찍기 시작]을 누르면 별 이름이 하나씩 뜨고, 지도에서 그 별을
   **한 번 누르면** 그 자리로 확정되고 다음 별로 넘어간다. 옆 확대 창으로 자국 한가운데인지
   확인하고, 어긋나면 창 안을 끌어 원본 픽셀 단위로 미세 조정한다.
   [채색본으로 보기]로 배경을 바꿔 한자 이름을 확인할 수 있다.
   핀은 옮기는 즉시 저장되므로 새로고침해도 날아가지 않는다.
2. **② 단계 3 확대 영역** — 전체 지도에서 삼수 자리에 사각형을 맞춘다.
   ⚠ 기본값은 눈으로 확인하지 않은 어림값이므로 **반드시 확인이 필요하다.**
   맞춘 뒤 "이 영역을 눈으로 확인함"을 켠다.
3. **③ 단계 4 별 3개** — 크기 차이가 잘 드러나는 밝은·중간·어두운 별을 고른다.
4. **[서버에 저장]** — 개발 서버로 열었다면 `config.json` 이 저장소에 바로 써진다.
   그 파일을 커밋해 배포하면 학생 태블릿이 모두 그 설정을 쓴다.
   (다른 환경이면 [config.json 내보내기] 로 내려받아 저장소 최상위에 둔다)

설정 우선순위는 **`config.json` → localStorage → 기본값**.
"config.json 보다 이 기기 설정을 우선 사용"을 켜면 그 기기에서는 localStorage가 이긴다.

## 배포

**Cloudflare Workers** 로 배포한다. 학급 실시간 투표가 Durable Object 를 쓰므로
Pages 가 아니라 Worker 여야 한다.

```bash
npm install
npx wrangler login      # 처음 한 번만
npm run deploy
```

주소는 `https://josunstellar.<계정>.workers.dev` 형태로 나온다.
`public/` 안의 화면·이미지는 Workers Assets 가 그대로 내보내므로 빌드 단계가 없다.

- 교사용 — 주소 뒤에 `?admin=1`
- 학생 — 첫 화면에서 [코드로 참여하기]

캘리브레이션을 고쳤으면 `public/config.json` 을 커밋하고 다시 배포한다.

### 학급 기능을 빼고 정적으로만 쓰려면

`public/` 폴더만 아무 정적 호스팅에 올려도 된다.
Cloudflare Pages 는 build output directory 를 `public`, GitHub Pages 는 `/public` 으로 둔다.
참여 칸은 스스로 접히고 나머지 8단계는 그대로 동작한다.
`_headers` 가 캐시를 잡아 준다 — 지도 이미지는 7일, 코드(HTML·JS·CSS)는 매번 확인.
코드에 max-age 를 주면 안 된다. index.html 만 새것이고 JS 가 낡으면 화면과 코드가
어긋난 채로 돌아가, 배포 직후 그 시간 동안 학생 기기에서 앱이 깨질 수 있다.
이미지를 교체했는데 옛 그림이 보이면 파일 이름을 바꿔 올리면 바로 반영된다.

```bash
npm run dev        # wrangler dev — 학급 기능까지 그대로 돌아간다
```

`node tools-serve.js 8123` 은 Worker 없이 화면만 볼 때 쓰는 간이 서버다.
캘리브레이션의 [서버에 저장] 은 이 간이 서버에서만 동작한다
(`wrangler dev` 로 띄웠을 때는 [config.json 내보내기] 를 쓴다).
